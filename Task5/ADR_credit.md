### <a name="_qmphm5d6rvi3"></a>**Решение**
![Диаграмма контекста](mvp_credit_c4_context.png?raw=true "Диаграмма контекста")

![Диаграмма контейнеров](mvp_credit_c4_container.png?raw=true "Диаграмма контейнеров")

**Логика принятия решений:**
1. **Использование существующей инфраструктуры:** Кредитный конвейер и система скоринга уже работают. Нужно только подключить к ним новые каналы входа.
2. **Минимальные изменения:** Не создаем новые сервисы там, где можно использовать существующие.
3. **Соблюдение ограничений:** Используем интеграционный слой (Kafka) для взаимодействия с АБС, как в решении для депозитов.
4. **Простота MVP:** Для предодобренных предложений используем данные из существующего скоринга, не создавая отдельный сервис.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**
**Создание отдельного "Кредитного портала".** Разработка нового отдельного приложения специально для онлайн-кредитования.

Недостатки, ограничения, риски:
- Дублирование функциональности, дорого, долго, клиентам нужно осваивать новое приложение.

### <a name="_bj3d7veeh34c"></a>**Недостатки, ограничения, риски выбранного решения**

1. Задержка в обработке: Данные из АБС в систему скоринга поступают раз в сутки, поэтому скоринг может использовать не самые актуальные данные о клиенте.
2. Нет предодобренных предложений в MVP: Для показа предодобренных предложений в интернет-банке нужно дорабатывать систему скоринга для фоновых расчетов.
3. Зависимость от БКИ: При недоступности БКИ новые клиенты не могут получить решение по заявке.
4. Старый стек интернет-банка: Сложности с интеграцией новых функций в устаревший .NET Framework.
5. Ручная обработка: В MVP заявки все равно обрабатываются сотрудниками вручную, полной автоматизации нет.
