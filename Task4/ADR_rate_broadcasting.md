### <a name="_qmphm5d6rvi3"></a>**Решение**
![Диаграмма контекста](rate_broadcasting_c4_context.png?raw=true "Диаграмма контекста")

![Диаграмма контейнеров](rate_broadcasting_c4_container.png?raw=true "Диаграмма контекста")

**Логика принятия решений:**
1.  **Единый источник истины:** Сервис НСИ, уже созданный в рамках MVP, становится единственным источником ставок для всех систем. Это соответствует принципу DRY и обеспечивает консистентность данных.
2.  **Два канала распространения:** Для внутренней системы кол-центра — **REST API** (оптимально для real-time обновлений). Для внешнего партнёра — **выгрузка файлов на SFTP** (единственный технически возможный вариант, соответствует ограничению).
3.  **Безопасность SFTP:** Использование существующей инфраструктуры банка для SFTP-сервера. SSH-ключи для аутентификации партнёра обеспечивают необходимый уровень безопасности.
4.  **Простой и надежный формат:** CSV выбран как наиболее универсальный и понятный формат для интеграции с внешней системой (предусматривает в том числе возможные легаси).
5.  **Кэширование в кол-центре:** Для снижения нагрузки на НСИ и обеспечения отказоустойчивости, система кол-центра будет кэшировать полученные ставки с TTL (Time To Live), обновляя их по расписанию (раз в час).

### <a name="_bjrr7veeh80c"></a>**Альтернативы**
**Прямое подключение партнёрского кол-центра к API НСИ через VPN.** Организация защищённого VPN-туннеля между сетями банка и партнёра, чтобы партнёрская система могла вызывать REST API НСИ напрямую.

Недостатки, ограничения, риски:
- Техническая сложность: требует настройки и поддержки межсетевого взаимодействия;
- Нарушение границ безопасности: открывает внутренний API банка для внешней системы;
- Не соответствует ограничению: партнёр технически не готов к API-интеграциям.
- Жёсткая связь: изменения в API НСИ потребуют синхронных изменений у партнёра.

**Передача ставок через общую облачную папку (S3, SharePoint).** Использование облачного хранилища как промежуточной точки для обмена файлами.

Недостатки, ограничения, риски:
- Зависимость от облачного провайдера: требует наличия и настройки облачной инфраструктуры;
- Дополнительные затраты: оплата облачного хранилища и трафика.

**Внедрение отдельного "Сервиса справочников" для внешних потребителей.** Создание упрощенного, публичного API поверх НСИ специально для внешних систем (партнёров).

Недостатки, ограничения, риски:
- Избыточность: создание и поддержка ещё одного сервиса без необходимости;
- Увеличение времени разработки: откладывает решение насущной проблемы;
- Дублирование логики: необходимость синхронизации данных между НСИ и этим новым сервисом.

### <a name="_bjdr7kieh82c"></a>**Недостатки, ограничения, риски вы**
1. Задержка данных у партнёра. Партнёрский кол-центр работает на данных, которые могут быть актуальными на момент выгрузки (например, утром), но не в реальном времени. При изменении ставок в течение дня партнёр узнает об этом только на следующий день.
2. Риск несогласованности формата файла. При изменении структуры данных в НСИ (добавление новых полей) необходимо синхронно менять логику формирования файла и предупреждать партнёра об изменениях формата.
3. Нагрузка на SFTP-сервер. При масштабировании (подключение новых партнёров) SFTP-сервер может стать узким местом и потребовать администрирования.
4. Отсутствие подтверждения получения. 
5. Дополнительная сложность НСИ. Компоненту выгрузки в файл потребуется сопровождение: мониторинг успешности выполнения, обработка ошибок, ротация старых файлов.
